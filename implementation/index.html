Implementation

Build the control system first

The architecture is implementable with technology available today. The delivery risk is not model capability. It is uncontrolled coupling between state, reasoning, authority and side effects.

Build order

0
Scope one claim archetype

Product, event, authority and control boundaries.

1
Claim State + event model

Versioning, provenance and material events.

2
Timers + communication

Obligations become executable early.

3
Readiness + HITL

Candidate action, evidence and hard controls.

4
One intelligence domain

Prove bounded reasoning and provenance.

5
One side-effecting action

Idempotency, error handling and reconciliation.

6
Expand by evidence

Add domains/actions only after controls and metrics hold.

Build the orchestrator before the agents

The hardest part is not creating an agent that can read a claim. The hard part is deciding what a claim is allowed to do when different evidence arrives at different times, a customer has different needs, a supplier is late, a complaint is open and one decision is ready while another is not.

Build the state, orchestration, controls, human decision contract and side-effect safety first. Intelligence services can then be added behind stable interfaces.

Anti-patterns

  • One “claims agent” with permission to decide and execute everything.
  • Recreating the existing linear workflow in BPMN and calling it transformation.
  • A global parallel join that waits for every domain to finish.
  • Confidence thresholds hard-coded as decision authority.
  • Customer evidence requests generated before checking information already held.
  • Human review tasks that block unrelated actions.
  • Payments or repair instructions without idempotency/reconciliation.
  • A separate complaint workflow that loses the original claim context.
