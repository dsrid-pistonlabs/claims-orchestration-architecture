Reference architecture

The claim is a state, not a stage

The architecture only works if there is a durable, versioned and auditable place to coordinate facts, evidence, findings, unknowns, candidate actions, obligations and outcomes.

Claim State is the coordination backbone

A persistent Claim State is not a giant summary blob. It is a versioned, attributable representation of what the organisation currently knows, what remains uncertain, what it is considering doing, what it has done and which obligations are active.

Identity and policy context

Claim ID, policy/version, insured/beneficiary/representative, product, event date, provisional/verified status.

Event facts

Structured facts with source, timestamp, status, confidence/reliability and supersession history.

Evidence inventory

Documents, media, external data and reports with provenance, access controls, integrity metadata and links to findings/decisions.

Intelligence findings

Coverage, damage/quantum, liability, integrity, customer context, recovery and economics findings with evidence links and material unknowns.

Candidate actions

Possible next actions, prerequisites, consequence, reversibility, evidence sufficiency, human requirement, control status and execution state.

Decision records

Decision type, basis, evidence, relevant rule/policy clause, model/rule/service version, human rationale/override, authority and timestamp.

Customer context

Communication preference, support needs, vulnerability/hardship signals, representation, interpreter/accessibility needs and interaction history.

Obligations and timers

Code, complaint, investigation, privacy, supplier, service and internal timers, with pause/exception/alternative-timetable state where applicable.

Execution and external work

Appointments, repair/payment/settlement, supplier milestones, recovery, investigation and exception events.

Audit and residual work

Material event stream, prior state versions, linked complaint/recovery/litigation cases, retention and closure evidence.

State rules

  • Every material fact retains provenance and can be superseded without erasing history.
  • Findings link to evidence. Decisions link to findings/evidence/rules/human rationale as applicable.
  • Unknowns are first-class data. An unresolved field is not silently converted into a low-confidence fact.
  • Candidate actions can be independently ready, blocked, released, failed or completed.
  • Customer and obligation state can change the process even when loss facts do not.
  • State updates publish material events so dependent services re-evaluate only when necessary.

Privacy, security and audit

Claim State concentrates sensitive information and therefore needs explicit purpose, access, data-quality, retention, security and audit design. For APRA-regulated insurers, the implementation also needs to fit the entity’s CPS 234 information-security framework and CPS 230 operational-risk/resilience framework. SRC-07 SRC-08 SRC-14 SRC-15
